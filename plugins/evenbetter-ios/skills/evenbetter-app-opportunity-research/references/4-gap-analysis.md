# Stage 4: Gap analysis

Turn the stage 2 and 3 findings into a feature comparison matrix. This is where an opportunity becomes concrete. Link each row to the sources behind it.

```markdown
| Feature            | App A | App B | App C | App D | Opportunity |
|--------------------|-------|-------|-------|-------|-------------|
| Core Feature 1     | ✓     | ✓     | ✗     | ✓     | Table stakes |
| Core Feature 2     | ✗     | ✓     | ✓     | ✗     | Table stakes |
| Gap Feature 1      | ✗     | ✗     | ✗     | ✗     | Differentiator |
| Gap Feature 2      | ✗     | ✗     | ✗     | ✗     | Differentiator |
| AI Integration     | ✗     | Basic | ✗     | ✗     | Differentiator |
| Price (monthly)    | $14.99| $9.99 | Free  | $6.99 | Undercut + better value |
| UX Quality         | Poor  | Good  | OK    | Good  | Win on polish |
```

The strongest opportunity sits where all four of these hold:

1. **Proven demand.** Several competitors exist and make money.
2. **Consistent gaps.** They all miss the same one or two features users want.
3. **Vocal frustration.** Users complain about that gap in public.
4. **Viable pricing.** The category supports subscriptions of $5 a month or more.

## Exit

Add the matrix to `research-notes.md` with a source link per row, then move to stage 5.
